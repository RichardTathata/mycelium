# The causal door registry (docs/plans/adopter-surface.md X4): every door that starts dependent work, and how the
# two causal fields (`correlation`, `parent`; src/agent/causal.rs) travel through it. In the shape of the fuzz
# reachability registry: this list claims completeness, and scripts/check-causal-doors.py fails on a door it
# finds in the code that has no row here, and on a row whose test does not exist.
#
# Columns, `|`-separated:  door  |  carries  |  test
#   door     <file>::<symbol> — the file and the handler, verb or function the scanner finds (see the script's SCAN)
#   carries  record      the door runs the preflight and writes a record carrying the fields it read from the payload
#            record+fwd  …and forwards them to the provider inside the application payload (parent = its own decision)
#            bytes       the door passes application bytes it does not alter; the provider reads them if its kind's
#                        payload is JSON (`mcp.invoke`); no record is written at this door
#            none        no record is written at or beyond this door; nothing reads the fields (stated, not a defect)
#            refused     the door refuses protected kinds, so no governed work starts here
#   test     the `fn` that shows it, in src/ or tests/; `-` with the reason after a `#` when there is none (a gap the
#            registry states rather than hides)
#
