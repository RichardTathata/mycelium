# What is proven — and what is not

↑ [Operations](README.md) · beside the [shared-responsibility matrix](shared-responsibility-matrix.md)

**As of 2026-10-11 (v2.32.0).** One dated page for the line between what CI proves on every merge,
what has been demonstrated with its bound stated, and what has not yet been shown. Every line names
its evidence. The places that used to restate this list — `CLAUDE.md` § Active work, the contracts-axis
plan §10, the self-audit series, the publications ledger, both decks — now link here instead, and
`RELEASING.md` § 6 refreshes this page at every release. It exists because each gap below was already
stated honestly somewhere, and a reviewer assembling them from six places assembles them against us.

> **How to read it.** *Proven* means a deterministic gate that turns red on regression, run by CI on
> every merge. *Demonstrated* means it was run and measured, with the bound or the condition stated,
> but not on every change. *Not yet shown* means exactly that, with what would show it.

## Developer teaching checks added 2026-10-02

The [new learning path](../guide/tutorials/README.md) adds the
`first_stem_fleet` example and `scripts/check-stem-observations.py` to the
`wasm-host` CI job. The checks cover a signed echo component, useful invocation,
graceful provider replacement, a schema-validated declaration/observation join,
and missing-provider, unknown-unit, duplicate and invalid-schema refusals.
It runs on every change (`ci.yml`, the `wasm-host` job). The local
fleet run and all five consumer checks passed on 2026-10-02; validation scope is
recorded in the [teaching-path ingest](../wiki/dev/.log/2026-10-02-developer-teaching-path.md).

This is one local fleet and a scenario-specific consumer. It does **not** close
the deployment, multi-machine recovery or NovusLens consumer-rendering gaps below.

| **Combined-feedback oscillation** | not posed — the three control loops share one state variable and neither isolation method can ask the question | a second state variable, or a different instrument |
| **Disaster recovery of an electorate that lost its majority** | **not built.** Ordinary consensus cannot authorise its own repair — a minority cannot know what the majority decided — so the group stays stopped. What it would take is an operator-forced genesis from the survivors' durable acceptor records (`sys/consensus-accepted/{node}/{slot}`, read off their persistence directories), with every decision only the lost members had accepted stated as possibly lost; nothing in the tree does this. The adjacent hazard is stated instead of closed: a member restarted under its `NodeId` over an **empty or older** store is not detected (`prewarm_accepted` restores what it finds; `start()` does not refuse an electorate member with no acceptor records), so every operator page says *restore with the latest persistence directory, or retire onto the removal ledger — never reissue the identity empty* (2026-10-11 correction of 2.32.0's "replace hardware under the same identity") | the procedure itself, shown on a three-member group that lost two; and a start-time refusal (or warning) for a known electorate member whose store holds no acceptor records |
| **The check-then-act window** | narrowed and stated per site, not eliminated (`late_writes()` counts them) | it cannot be eliminated by this design; the count is the claim |
| **Identity proofs required by default** | `require_identity_proofs` is default-off. The 2026-09-24 revert's stated cause (identity and proof as two independent gossip writes) was wrong — the flag is inert without TLS, and 2.14.0's sealed record (`sys/identity-signed/`) closed that window by construction; what remains is the residual `docs/wiki/dev/security.md` § *The limit none of this closes* states: first sighting of an unseen node is trust-on-first-use with or without proofs, and only anchors close it. A commitment signature's strength rests on the flag; `clock_sync` is always `Unverified` | a deployment that turns it on today; a release that flips the default once anchors close the first-sighting residual it would otherwise merely rename |
| **A composed effect reconstructable from one shipped record** | the record *can* carry the receipt's rung and the origin domain (`AeEvidence::with_effect_durability` / `with_origin_domain`, 2.11.0) and `states_a_composed_effect()` reads them — but no shipped path calls either builder: the gateway's evidence path writes neither field, so every record it produces has both `None` and the predicate false; the only callers are the module's own tests (`src/agent/action_evaluator.rs`; the 360 review, 2026-10-09). `composed-effect.md` §9 says the fields are available to an enforcement point, not written by one | an enforcement point that writes both fields onto the record it journals, with a test that reads a composed claim back from a journal the gateway wrote |
| **Every signature the substrate verifies is domain-tagged** | the identity proof (`mycelium.identity/proof/1`), the consensus payload (`mycelium.consensus/msg/1`) and, since post-360 row F, KV `SignedData` (`mycelium.kv/update/1`) are — that half is now in the CI table above; **role claims (`SignedRoleClaim`) and audit records** are still signed over untagged canonical bytes. Neither can begin with another domain's tag, so the tagged verifiers are closed to them, but one of the two could still be presented *as the other* | a MINOR that tags the two, with the same one-release allowance as `deprecations.md` §23 and §35 |
| **The cost of recording each acceptor answer** | since 2.32.0 an acceptor's promise and vote reach stable storage (one forced `fdatasync`, serialised on the listener) before the answer leaves; its effect on consensus latency is not measured | a latency measurement of group proposals with and without `[persistence]`, in the shape `examples/authority_drain` takes |
| **The accept path against a peer that keeps talking** | bounded against silent and slow connections only (row B as narrowed 2026-10-11): an attacker that keeps sending complete frames holds the connection slots it obtained from free permits, up to `max_connections`; mitigated by mTLS and the opt-in `max_connections_per_source` (exact IPs; an IPv6 /64 is not covered). Connection preemption was built and removed in #602's review rounds 3–5 because it displaced honest peers | a per-identity limit on a TLS mesh, or a preemption rule that cannot displace an honest peer, with a test that holds every slot and still admits a member |
| **The write side against a slow reader** | no rate floor, deliberately (a sender cannot tell a slow link from an applying `flush` receiver): a peer that reads one byte per `peer_write_stall_timeout_ms` (19 min by default, 1.5 × the measured 760 s worst chunk apply) parks its own writer and its one anti-entropy reply for as long as it keeps doing so — up to `max_peers` × the divergent store | a receiver that signals apply progress, so the sender can tell the cases apart |

| **The declaration as a consumer record, rendered by the consumer** | the schema is pinned and every edge carries its call shapes (W6, public); the private companion ships the `deployment_declaration` batch on the `v2.17.0` pin, retry-identical, accepted by its stub consumer, the join tested on the co-op golden (companion PR #4, 2026-09-30) | the consumer (NovusLens) accepting a real batch and rendering a declared edge beside its observations — on their side of the handover |

not *shown*. A line moves from the third table to the first only with a gate CI runs, and the move is
dated here.
