# What is proven — and what is not

↑ [Operations](README.md) · beside the [shared-responsibility matrix](shared-responsibility-matrix.md)

**As of 2026-10-27 (v2.38.2).** One dated page for the line between what CI proves on every merge,
what has been demonstrated with its bound stated, and what has not yet been shown. Every line names
its evidence. The places that used to restate this list — `CLAUDE.md` § Active work, the contracts-axis
plan §10, the self-audit series, the publications ledger, both decks — now link here instead, and
`RELEASING.md` § 6 refreshes this page at every release. It exists because each gap below was already
stated honestly somewhere, and a reviewer assembling them from six places assembles them against us.

> **How to read it.** *Proven* means a deterministic gate that turns red on regression, run by CI on
> every merge. *Demonstrated* means it was run and measured, with the bound or the condition stated,
> but not on every change. *Not yet shown* means exactly that, with what would show it.

## Developer teaching checks added 2026-10-02

The [new learning path](../guide/tutorials/README.md) adds the
`first_stem_fleet` example and `scripts/check-stem-observations.py` to the
`wasm-host` CI job. The checks cover a signed echo component, useful invocation,
graceful provider replacement, a schema-validated declaration/observation join,
and missing-provider, unknown-unit, duplicate and invalid-schema refusals.
It runs on every change (`ci.yml`, the `wasm-host` job). The local
fleet run and all five consumer checks passed on 2026-10-02; validation scope is
recorded in the [teaching-path ingest](../wiki/dev/.log/2026-10-02-developer-teaching-path.md).

This is one local fleet and a scenario-specific consumer. It does **not** close
the deployment, multi-machine recovery or NovusLens consumer-rendering gaps below.

| Gap | State on 2026-10-26 | What would show it |
|---|---|---|
| **Binary provenance** | the Release workflow (adopter-surface X0) attaches `SHA256SUMS` to every tag's tarballs and pushes the image by digest: integrity of the download, not provenance of the build; nothing signs a binary or the image, and reproducible builds are not claimed | a Sigstore or GPG signature on each tarball and the image, verified by the clean-container smoke before the assets are attached |

| **Performance under load** | only the micro-benchmarks above; no end-to-end throughput or latency figure for a cluster under sustained load, and the benches are not run in CI | a load run on a real network with the numbers in `tuning.md`, and a bench job with a stored baseline |
| **AE4 — the four joint AWS/GCP runs** with the oversight consumer | the Cedar adapter and the signed exporter are implemented in the private companion, pinned to this release; the joint runs have not happened, and a local fixture does not stand in for them | the runs themselves; §6.8 of the axis plan says neither a fixture nor one cloud can close it |
| **Models pulled from S3 or GCS** | the adapter exists (S2: `ObjectStoreFetcher` over the `object_store` crate — S3, GCS, Azure, HTTP, local — ranged, egress-gated, the manifest in the store), exercised in CI against an **S3-compatible mock** (Adobe's S3Mock) and locally over `file://`; the same test takes a GCS URL, but **no GCS emulator runs**: `fake-gcs-server` accepts only signed-URL uploads and the crate puts with a plain PUT (S3 ◐, two CI runs); **no real bucket has been used** | `design-time-tooling.md` S4 (real buckets, delivery evidence, dated) |
| **The self-audit floor** | 7 / 7 / 7 for Modularity, Performance and Operational Readiness / Developer Experience across many runs (Run 62, 2026-09-26); the calibration ledger holds **48 entries** of scores later proven wrong | fresh execution evidence per dimension, not a re-asserted number — the M2 rule |
| **Combined-feedback oscillation** | not posed — the three control loops share one state variable and neither isolation method can ask the question | a second state variable, or a different instrument |
| **Disaster recovery of an electorate that lost its majority** | **not built.** Ordinary consensus cannot authorise its own repair — a minority cannot know what the majority decided — so the group stays stopped. What it would take is an operator-forced genesis from the survivors' durable acceptor records (`sys/consensus-accepted/{node}/{slot}`, read off their persistence directories), with every decision only the lost members had accepted stated as possibly lost; nothing in the tree does this. The adjacent hazard is stated instead of closed: a member restarted under its `NodeId` over an **empty or older** store is not detected (`prewarm_accepted` restores what it finds; `start()` does not refuse an electorate member with no acceptor records), so every operator page says *restore with the latest persistence directory, or retire onto the removal ledger — never reissue the identity empty* (2026-10-11 correction of 2.32.0's "replace hardware under the same identity") | the procedure itself, shown on a three-member group that lost two; and a start-time refusal (or warning) for a known electorate member whose store holds no acceptor records |
| **The check-then-act window** | narrowed and stated per site, not eliminated (`late_writes()` counts them) | it cannot be eliminated by this design; the count is the claim |
| **Recovery from a compromised fleet CA key** | **not built.** Since 2.33.0 (row Q) revocation authority rests on certificates, so a holder of the fleet CA key can issue a certificate that outranks any node's key — and in the development posture every node holds it (`auto_cert_dir`'s `ca-key.pem`); the secure posture keeps the key off-node (`id.ca_key_off_node`) but cannot rotate and recovers by re-issue only | the CA key off every node by default (a start-time warning when it is on the node is delivered, row T, 2.34.0; the handshake check against the revocation records is delivered, row Q's follow-up) |
| **Anti-entropy entries authenticated** | since row F2 a TLS node refuses every unsigned and bare-signed KV gossip frame (the first table), but an anti-entropy `StateResponse` entry carries no author and no signature and is applied by LWW, so a member can still introduce a value for any key through a state reply; the `sys/` tripwire does not count an entry for a key the victim holds nothing under. Restated by row F2, not closed | a `SyncEntry` that carries its originator's id and signature, verified on receipt as the `SignedData` arm verifies — a wire change (v13), with its own mixed-fleet window |
| **A persisted node's recording replays decision for decision** | **found diverging** by X6's `replay` class (2026-10-24): a node with `[persistence]` replays to seq ~37 and departs between its first WAL write (`fs wal.bin write_all`) and the governor's `jitter` draw — two seams whose order the schedule decides, which the scheduler seam does not yet arbitrate for the kv-persist writer; the Z5 proof above is over a node without persistence | the kv-persist writer's first write taken through the scheduler seam's arbiter, then `test --faults replay` against a configuration with `[persistence]` green in CI |
| **An external side-effect at a real provider** | the side-effect contract (adopter-surface X5, `mycelium::effects::external` since X9 — the companion re-exports it) is proved against the SQLite destination and a **mock HTTP destination** whose harness loses responses on demand — the unknown path, the probe, the one retry, the budget, the compensation, the egress gate and the zero-reach replay are each a CI-run test (`tests/external.rs`, `external_evidence.rs`, `external_replay.rs`); no payment or cloud provider has been run against it, and the reference HTTP destination attaches no credential | a provider adapter run against a sandbox account, with the lost-response case induced there, and credential binding at egress on it |
| **A composed effect reconstructable from one shipped record** | the record *can* carry the receipt's rung and the origin domain (`AeEvidence::with_effect_durability` / `with_origin_domain`, 2.11.0) and `states_a_composed_effect()` reads them — but the gateway's evidence path calls neither builder, so every record it produces has both `None` and the predicate false (`src/agent/action_evaluator.rs`; the 360 review, 2026-10-09). Since adopter-surface X5 one shipped path does: `mycelium-effects`' reconciler writes `origin_domain` when the composition carries one and `effect_durability: on_disk` for a **local** destination's commit — a remote commit is the destination's claim, which the local rung cannot name — and no test asserts the predicate on its records. `composed-effect.md` §9 says the fields are available to an enforcement point, not written by one | an enforcement point that writes both fields onto the record it journals, with a test that reads a composed claim back from a journal the gateway wrote |
| **Every signature the substrate verifies is domain-tagged** | the identity proof (`mycelium.identity/proof/1`), the consensus payload (`mycelium.consensus/msg/1`) and, since post-360 row F, KV `SignedData` (`mycelium.kv/update/1`) are — that half is now in the CI table above; **role claims (`SignedRoleClaim`), audit records and revocation events** (`src/agent/revocation.rs`) are still signed over untagged canonical bytes. None can begin with another domain's tag, so the tagged verifiers are closed to them, but one of the three could still be presented *as another* | a MINOR that tags the three, with the same one-release allowance as `deprecations.md` §23 and §35 |
| **The cost of recording each acceptor answer** | since 2.32.0 an acceptor's promise and vote reach stable storage (one forced `fdatasync`, serialised on the listener) before the answer leaves; its effect on consensus latency is not measured | a latency measurement of group proposals with and without `[persistence]`, in the shape `examples/authority_drain` takes |
| **The accept path against a peer that keeps talking** | bounded against silent and slow connections only (row B as narrowed 2026-10-11): an attacker that keeps sending complete frames holds the connection slots it obtained from free permits, up to `max_connections`; mitigated by mTLS and the opt-in `max_connections_per_source` (exact IPs; an IPv6 /64 is not covered). Connection preemption was built and removed in #602's review rounds 3–5 because it displaced honest peers | a per-identity limit on a TLS mesh, or a preemption rule that cannot displace an honest peer, with a test that holds every slot and still admits a member |
| **The write side against a slow reader** | no rate floor, deliberately (a sender cannot tell a slow link from an applying `flush` receiver): a peer that reads one byte per `peer_write_stall_timeout_ms` (19 min by default, 1.5 × the measured 760 s worst chunk apply) parks its own writer and its one anti-entropy reply for as long as it keeps doing so — up to `max_peers` × the divergent store | a receiver that signals apply progress, so the sender can tell the cases apart |
| **An older reader during the lock-lifecycle upgrade** | an upgraded node still writes the legacy keys and `Commit`, and a 2.31 reader still reads them the old way, so the K3 re-stamp and rounds 1–2's pairings remain for it until it is upgraded; a permanent decision whose original proposer is gone for good cannot be released by anyone else (`docs/design/lock-lifecycle.md` §5); the SDKs expose no `release_leadership` verb | the legacy keys retired at a governed MINOR; an SDK release verb (row G) |
| **The declaration as a consumer record, rendered by the consumer** | the schema is pinned and every edge carries its call shapes (W6, public); the private companion ships the `deployment_declaration` batch on the `v2.17.0` pin, retry-identical, accepted by its stub consumer, the join tested on the co-op golden (companion PR #4, 2026-09-30) | the consumer (NovusLens) accepting a real batch and rendering a declared edge beside its observations — on their side of the handover |

## What this page is not

It is not the threat model, the shared-responsibility matrix or the production-readiness checklist;
those say what the library provides and what you own. This page says what the project has and has
not *shown*. A line moves from the third table to the first only with a gate CI runs, and the move is
dated here.
