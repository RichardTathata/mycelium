## [2026-09-30] ingest | X2, second slice: the stem re-serves its cache, and bridges a tool

**What:** two stem capability gaps closed. `Stem` on the mesh path runs `serve_artifacts` over its
`MeshArtifactSource` and advertises `artifact/librarian` (`role = "cache"`) once the cache holds
something, so a late joiner installs from a peer after the librarian is gone (the catalog demo's
phase 6, now in the stem-examples suite: the driver kills the librarian and `docker run`s a late
stem). `WasmComponentRuntime::install` registers a `tool/{name}` component as MCP tool `{name}`
(feature `gateway`; the handle dies with the install), so the tool-growth demo runs as stems too.

**Durable knowledge:**
- **Advertise the cache only once it holds something.** A peer's pull walks the holders in order and
  stops at the first that answers; an empty cache advertised early would answer "not held" harmlessly,
  but it is still a claim about nothing — so the advertisement waits for the first verified bytes.
- **The bridge is a forward, not a second instance.** The MCP handler calls the component's own serve
  loop over `cap.invoke/tool/{name}` on the local node, so the fuel budget, the invocation record and
  the trapped-instance replacement (F1) all apply to a call that came in through the MCP door.
- **Two doors, one component**: `tool/{name}` as a capability (resolvable, `cap.invoke`) and `{name}`
  as an MCP tool (`tools/{name}/{node}` in KV, `tools/call` over `mcp.invoke`). The demo's agent uses
  the second; the provisioner's demand uses the first.
