## [2026-09-15] ingest | v2.5.0 released (the contracts MINOR — receipts, caller identity, the AE seam)

Up: [dev](../dev.md) · ledger [history](../history.md) · plan `docs/plans/v3-contracts-axis.md` rev 1.12 ·
tag `v2.5.0` (`d0778c0`).

**Why a MINOR, not a PATCH.** The queue's first tranche adds public API — `set_with_receipt`,
`set_requiring_sync`, `prepare_write`/`commit_prepared`, `*_propose_receipt`, the `GatewayCaller` and
`ActionEvaluator` surfaces. New public API is `x.Y.0` under the runbook's §1 regardless of how small
each addition looks; 2.4.5 would have understated what a consumer is picking up. Wire **v12** (PREV 11)
and the on-disk format are unchanged, so the rolling upgrade holds.

**What shipped.** Item 7 (gateway caller identity — a provider sees the client principal behind a call,
issuer-qualified and node-attested, never the gateway node); item 1 PR 1/PR 2/PR 3 (the contracts ADR and
regression floor, the typed receipt vocabulary, the required local sync and the prepared write); the AE
evaluator seam and the AE0 ADR; item 6 PR 1's nondeterminism inventory; item 8's threat model rev 2; the
membership-governor cooldown parameter and `staleness_known`; and rustls 0.23.45 for RUSTSEC-2026-0285 —
**the `v2.4.4` tag ships the vulnerable version**, so that advisory is closed only from this tag forward.

**Two upgrade notes carried in the release summary,** both stated rather than buried. `authorized_callers`
now judges the *client principal*, so a deployment that listed a gateway's node id to admit its HTTP clients
must list those clients instead — that node-listing was the impersonation item 7 closes. And `GossipConfig`
gained a field, which is **not additive by Rust's rules**: an exhaustive struct literal stops compiling. The
documented `..Default::default()` pattern is unaffected, which is why the break passed unremarked through
every earlier config-field addition; the `3.0.0` ledger now carries the entry that ends the series.

**Gates.** `make check-full` green (441 tls / 490 compliance / 337 gateway-only / 179 core, full clippy
matrix incl. `--no-default-features`), the external-adapter test green, and all five wire gates green —
the rolling-upgrade trio plus `read_frame_accepts_prev_wire_version` and
`prev_wire_version_kv_write_is_applied_and_converges`. `WIRE_VERSION` unchanged, so §3's live two-binary
check does not apply. Bumped to 2.5.0: root, core, agentfacts, blackboard, tuple-space, wasm-host, wiki;
the independently-versioned companions stay on their own tracks.

because the step was backgrounded with the test gates. Restored here; the lesson is in
[the PR 3 entry](2026-09-15-item1-pr3-required-sync.md). *Second:* the ambiguity itself was real — the cut
2.5.0 section carried **two separate `### Added` headings**, a duplicate with precedent in this file (2.4.1
has two `### Fixed`). Merged into one immediately after tagging, entry set verified identical. The tag was
left where it stands rather than moved: a pushed tag is the release, and a heading tidy-up is not grounds
to rewrite one.
