# 2026-09-05 — v2.4.3 released (durability PATCH, same day as v2.4.2)

Cut **v2.4.3** (tag `v2.4.3`, release PR merged to `main`). Wire **v12** (PREV 11) unchanged; on-disk
format unchanged; no public-API change. Release gate: CI green on `a439f69` (the #181 merge) and on the
release PR before tagging.

**Why a second patch in one day:** v2.4.2's WAL-tail snapshot merge read `wal.bin` back with
`unwrap_or_default()`. A transient read error during a snapshot → a snapshot installed *without* those
records → step 4 truncates them. That is silent loss of acknowledged records — exactly the class v2.4.2
was cut to eliminate — one step past the race it fixed. The deterministic-replay design review (the third
external artefact of the day) named the read-back as a target for investigation; confirmed and fixed in
#181: `do_snapshot` propagates the read error (absent file = empty tail), nothing installed, nothing
truncated. Gate `regression_snapshot_aborts_when_wal_tail_is_unreadable` (wal.bin replaced by a directory
→ EISDIR — the one read failure injectable today without a filesystem adapter).

**Also between the two tags (companions, own tags):** `mycelium-py` 0.2.4 / `mycelium-ts` 0.1.1 —
gateway bearer on every handle (`token=` / `{ token }`, `MYCELIUM_GATEWAY_TOKEN`), `CommitResult {
persisted }` on `consistent_set` / `cross_group_propose`, `jest` CI-gated (#178, #179). ROADMAP v3.0
contracts axis recorded as proposed (#180-era docs, #181).

**Lesson carried into the wiki:** `unwrap_or_default()` on a read in a path that later *truncates* is a
data-loss primitive; the lint now greps persistence code for it.
