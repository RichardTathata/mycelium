# 2026-10-10 — the SDKs' edges with the gateway (post-360 hardening, row G)

- **What:** `mycelium-py` 0.2.10, `mycelium-ts` 0.2.4, `langgraph-checkpoint-mycelium` 0.3.3. Whole-second timeouts
  everywhere the gateway reads `timeout_secs` as an integer (Python's `rpc_call`/`scatter_gather` fractions were
  silently replaced by the route default; `emit_reliable`/`ingest` refused 422; the tuple `take` truncated
  `0 < t < 1` to a zero-second park); every caller- or row-supplied path segment percent-encoded, `.`/`..` refused;
  `mycelium-ts` `SupersededError`; `scatterGather` defaults to one reply and 10 s, as the gateway does.
- **The lesson:** encoding is not enough for a dot segment. The WHATWG URL parser reads `%2e%2e` as `..`, so
  `encodeURIComponent("..")` (which leaves it alone) and even a hand-encoded `%2E%2E` reach a different route from
  `fetch`; httpx keeps `%2E%2E` but a proxy may not. Both SDKs refuse the two values rather than send them.
- **The finding that mattered:** the checkpointer's blob id comes from a peer-writable `ckpt/` row; interpolated
  raw, `../../kv/keys?prefix=` sent the saver's bearer to `/gateway/kv/keys` (`tests/test_blob_path.py`).
- **Not built:** SSE reconnect. No gateway SSE route sends an event `id:` or reads `Last-Event-ID`, so there is no
  resume point for a client to use (plan decision D4: a feature with a window). Guide 10 § the HTTP surface lists
  what each stream loses on a drop. Noticed on the way: `log/group/subscribe` persists the group offset **before**
  sending the entry, so an entry in flight at a drop is not re-sent to the next consumer.
