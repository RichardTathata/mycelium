## [2026-10-12] ingest | post-360 row E: the gateway remainder (#PR)

- **Timer periods a client supplies are bounded.** `capability/advertise` and `units/declare` read `interval_secs`
  and `lease_secs` through one helper (`src/agent/http/caps.rs` `timer_secs`): absent → default, a whole number in
  `1..=3600` (`capability_config::MAX_TIMER_PERIOD_SECS`) → the period, anything else → 400 `timer_out_of_range`
  naming the field. The doors were enumerated by `grep -rnE '(secs|_ms|timeout|ttl|interval|period|lease)[a-z_]*"\]'
  src/agent/` and the `Deserialize` structs' time fields: every other gateway timer was already clamped
  (`timeout_secs` 1..=300, `ttl_secs` 1..=3600, `timeout_ms` via `gateway_rpc_timeout_ms`); these four were not, and a
  fraction silently became 30 s. A unit file's `ttl_secs` (the same period, reached by a stem and by `units/declare`)
  is held to the same range by `NodeCapabilityConfig::validate()`. Found on the way: a gateway advert gossiped a bare
  `Capability`, which every reader times at the legacy 60 s (`capability_ops::decode_cap_entry`), so an
  `interval_secs` above 180 flickered stale between beats — it now gossips a `CapEntry` with its own period, as an
  in-process advert does (every reader decodes both; `fixint` tolerates the trailing `u64` where a reader decodes a
  bare `Capability`).
- **The mailbox deletes an entry when the stream hands it on** (`src/agent/mailbox.rs` `open_mailbox_acked`,
  `MailboxAck`, `Sink::Acked`). The drain keeps an in-flight set (papaya, no lock) so an entry handed on and not yet
  acked is not queued twice; the ack tombstones *then* leaves the set, and the drain checks the set *then* the store,
  so a stale scan never re-sends an acked entry. "The client has it" at the HTTP layer means *the stream yielded the
  frame to the connection* — written to the socket is not received; what the connection and the kernel buffers held
  at a drop is still lost, and guide 10 says so. The in-process `open_mailbox` keeps tombstone-on-enqueue (it hands a
  plain `mpsc::Receiver`; the library cannot see it read) — stated in the module doc, not changed.
- **The log group's position is `(hlc, key)`, recorded after the hand-off** (`mycelium-core/src/log_cursor.rs`). The
  core sorted by `(hlc, key)` (`scan_log`) but both consumers kept an HLC-only offset, so a same-HLC sibling was
  skipped for ever (the gateway also sorted by HLC alone, so which one was arbitrary). The cursor lives at
  `clog/{stream}/{group}/cursor` beside the legacy `…/offset`, which is still written: a reader takes the cursor when
  it is at least as far as the offset, else the offset as *everything through this HLC* — so a mixed fleet agrees.
  The gateway records as its SSE stream yields (a `take_while` on an `active` flag stops a consumer that lost the
  claim from recording what it still had queued); the core records after `tx.send` succeeds and now exits when idle
  with its receiver gone (it looped for ever). The position moved from `apply_and_notify` + `try_send` to `kv_set`
  (WAL'd, signed under `tls`).
- **Prompt keys** go through `prompt::prompt_key` at every door that builds `prompts/{ns}/{name}` (`grep -rn
  'kv_ns::PROMPTS\|"prompts/' src/`): the three prompt routes, `llm/call`, `llm/stream`, and `LlmHandle`'s six verbs.
  An empty part or a `/` is refused; axum hands a `%2F` segment over decoded, which is how the SDKs' row-G encoding
  reached the alias. The provider's dispatch reads `prompts/{skill_id}` only for a registered id, so it needed no guard.
- **The caller envelope binds freshness** (`gateway_caller::verify`): its issue time was inside the signature and
  never read. Now older than `CALLER_CONTEXT_MAX_AGE_MS` (300 s — the gateway's longest wait) plus
  `max_clock_drift_ms`, or ahead by more than `max_clock_drift_ms`, is `CallerError::Stale`. One verifier covers every
  door (`rpc_rx`, the LLM provider, `rpc/serve`, provider enforcement, the emergent loop — `grep -rn
  'gateway_caller::verify'`). A replay inside the window is not refused: no nonce cache is built.
- `GatewayPreflight::is_inert` deprecated (no reference here or in `mycelium-private`); `mod.rs` cites the
  public-surface test by its real name. Fail-first outputs are quoted in the PR and the plan's §3.5 E block.
