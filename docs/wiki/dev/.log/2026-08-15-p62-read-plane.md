# ingest — P6.2: the read plane (2026-08-15)

**Shipped:** the persistent `git cat-file --batch` child on `GitStore` — blob reads become pipe
round-trips on one long-lived process (lazy spawn, respawn-once-on-death, Drop-reaped so no
zombies), replacing a `rev-parse` + `git show` spawn pair per page-read. `query`/`list_pages` now
share **one** head resolve + **one** `ls-tree -z` (`page_files_at`) instead of re-walking per page.
Bonus write-side win while in the plumbing: the per-file `update-index` loop became one
`--index-info` stdin splice — N files, one subprocess.

**Measured (the number the plan demanded before any scale claim on reads):** 600-page corpus,
`list_pages` + attribute `query` = **330 ms** (~0.55 ms/page) — extrapolated ≈3 s over Edinburgh's
5,741 committed files, vs the pre-fix estimate of tens of minutes (≈3 spawns/page). The gate
asserts <10 s (generous CI margin, still far below pre-fix cost) and prints the measurement.
