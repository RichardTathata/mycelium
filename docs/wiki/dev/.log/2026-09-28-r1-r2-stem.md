## [2026-09-28] ingest | R1/R2: the stem node and the stem fleet

**What:** `mycelium-wasm-host/src/stem.rs` (`Stem::start`, `StemOptions`, `StemSource`) and the
`mycelium-stem` binary (feature `stem`). `Provisioner::refresh_catalog` / `catalog()` added.

**Durable knowledge:**
- **D18's runtime half lives in the wasm-host crate, not the node binary.** The provisioner, the
  runtimes and the librarian are in `mycelium-wasm-host`, which depends on `mycelium`; the node binary
  cannot attach a provisioner without inverting the dependency. So `--units` is `mycelium-stem`'s
  flag, and the `mycelium` binary does not read the file. Recorded on the plan under D18.
- **The catalogue is a snapshot at construction.** `Provisioner::new` takes an `InstallableCatalog`;
  a node that starts before the librarian's entries gossip in would never see them. The stem refreshes
  from KV every tick — the reason `refresh_catalog` exists.
- **The provisioner does not prefetch.** `MeshArtifactSource::fetch` is a cache read; bytes must be
  `prefetch`ed first (the `catalog` demo does it by hand). The stem prefetches every catalogue entry
  each tick on the mesh path — bounded because the mesh path carries small artifacts only (the frame
  cap) — and the same source object must serve both the prefetcher and the provisioner, or the
  provisioner reads a cache nobody filled.
- `NodeId` has no `port` field: `to_socket_addr().port()`.
- No new lock: the ticker task owns the provisioner and publishes `hosted_count` through an atomic,
  so the lock-order table is unchanged.
- R2's gate is an **in-process** fleet test in the wasm-host CI job; the plan's "beside the coop
  suites" is met in that sense, and the Docker cut is recorded as open.
