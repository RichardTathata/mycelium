## [2026-10-26] release | v2.38.1 — zstd out of the tree (RUSTSEC-2026-0391, -0398, -0403, -0410)

- A security PATCH cut from the **v2.38.0 tag** on branch `release-2.38.x`, not from `main`: main carried unreleased Y1
  (#683) and Y7 (#685), which add public API (MINOR material). The fix is #686's manifest change, applied on the tag:
  `mycelium-wasm-host` depends on `wasmtime` with every default feature of 49.0.4 but `cache`.
- `zstd` reached the tree only through `wasmtime-internal-cache`, wasmtime's on-disk compilation cache; nothing in the
  repository calls its API, and `Config::new` leaves it `None`, so the compile path was the same without it. Upstream has
  no fix (wasmtime 50.0.0 still requires `zstd ^0.13`).
- `cargo audit -f` on all three tracked lockfiles: none of the four remains, nor the ten `zstd-safe` unsound warnings.
  `Cargo.lock` loses 14 crates and moves no version besides the train's.
- Ten train crates 2.38.0 → 2.38.1 (derived by the runbook's grep); the fuzz and conway-gpu lockfiles' `mycelium*` entries
  follow. Companions unchanged. Wire v12 unchanged; no API change.
- Anchors moved PATCH-sized, as v2.36.1 did: ROADMAP status, wiki version state, history, the CLAUDE.md on-ramp line,
  the install pins, `what-is-proven.md`'s header. `main` receives the `[2.38.1]` section and anchors by a follow-up PR,
  with #686's `[Unreleased]` Security entry moved into it.
- The tag is pushed **alone**: GitHub creates no push events when more than three tags are pushed at once, which is why
  v2.38.0's Release had to be dispatched on its tag.
