# Mycelium — wiki root

The project's LLM Wiki (schema: [AGENTS.md](AGENTS.md) — read it before editing; **code is
canon, the wiki cites it**). Start here, follow links down.

Mycelium is an embedded, broker-less Rust library: a three-layer substrate (gossip KV /
signal mesh / epidemic consensus) for AI agent fleets and storage replication, built on the
thesis that a coordinator is not just slower but *epistemically incapable* for heterogeneous
fleets. Purpose anchor: `docs/philosophy.md`. Version state: **v2.15.0 released** (2026-09-26, tag `v2.15.0` — **authority at every door**. Wire **v12** unchanged. v2.14.0's gateway decided authority per call and said honestly that it was *a route-level preflight at this gateway* — **a provider reached another way is not covered**. That sentence was a boundary; this closes it (Boundary H closure plan **C1–C12**). **Check before upgrading:** a client holding `mesh:write` could put `mcp.invoke` or `skill.invoke` in the body of `POST /gateway/rpc/call` (or `scatter`, `signal/emit`, `mailbox/deliver`, `shard/emit`, `overlay/emit_reliable`) and reach a provider **directly**, skipping the evaluator and every mandate check `/mcp` and `/a2a` run — those kinds now answer **`403 protected_kind`**. Beside it: a presented mandate **travels to the provider** so it can verify for itself; a provider can run the gateway's own preflight as enforcement point `provider`; cohort budgets admitted at the provider; **C7's bypass matrix** — after a revocation every door runs nothing, by the handlers' own counters, with a plant proving the doors reach them beforehand; a restart no longer restores revoked authority; the check-then-act window answered **per site** rather than denied; **work already running stops** when its authority lapses, **measured** against its class's bound (`examples/authority_drain`, in CI); every read of `Hlc::current()` classified and guarded by a CI script; and **an operator can remove a member** — a signed removal naming every key it held, refused at the TLS handshake, monotonic under `sys/membership/removed/`. Also the clock that was failing open: three expiry checks read a clock that never consults the wall clock, so on a quiet or partitioned node a mandate never expired. **Upgrade notes:** new scope **`mesh:serve`** for `rpc/serve`/`rpc/respond` (a `mesh:read`/`mesh:write` token is admitted there for **one release**, with a warning); protected kinds answer 403; `GitStoreConfig` gained `authority`; `[[bin]] mycelium` requires `cli`. **Not claimed:** the check-then-act window is **narrowed and stated, not eliminated** (the wiki store counts `late_writes()` rather than promising zero); `clock_sync` is always `Unverified`; provider enforcement **fails closed without an evaluator**, so a provider attaching none enforces nothing); before it **v2.14.0** (2026-09-25, tag `v2.14.0` — **coordination that says what it means**. Wire **v12** unchanged. A design note asked whether role accumulation is constrained anywhere; the answer was **no** twice over — not prevented (the design working: *detection, not prevention*) and **not detected either**, because every single-writer ring elected by *lowest candidate node id wins*, putting **every single-writer job on one node** while the seven existing detectors watched other axes (P2 churn, P6 gaps). **P10** makes it visible; **`mycelium::election`** stops producing it, the rule negotiated from the candidate set rather than flag-dayed. Then an attempt to make `require_identity_proofs` default-on was reverted — and the failure it was blamed on turned out not to be its doing, which sent us to read the election path properly. What was found there is the substance: an election over a roster a node **cannot see** counted as one member with a quorum of one, so **every node elected itself**; a **vote did not say what it voted for**, and ballots come from a shared key, so two proposers could commit **different values at one ballot**; a node could **equivocate with itself**, its proposer and acceptor roles keeping separate memories; a higher ballot **overwrote** a value a quorum had already accepted; and none of that memory **survived a restart**. All five closed. Beside them: identity and its proof travel as **one record**, a leadership answer **names the rung it reached** and carries a fencing token, and `POST /gateway/kv` no longer succeeds at writing nothing. **The limit, on the tin:** none of this makes leadership an exclusive grant that stays true — exclusivity is enforced **at the resource**, by refusing a stale token. **Upgrade notes:** `ConsensusResult` is `#[non_exhaustive]` and a `_` arm must fail closed; `FleetSnapshot` gained a field; a `POST /gateway/kv` without `value_b64` is now **400**; while any voter is un-upgraded, proposals from an upgraded proposer **time out** rather than commit. **Not claimed:** rendezvous is a spread, not a bound (which is why P10 stays); *proofs required* is not *identity authenticated*; and single-decree safety is not a proof of the whole protocol); before it **v2.13.0** (2026-09-23, tag `v2.13.0` — **the axis' last open questions, and a gateway that was not closed**. Item 2's **row 11 complete** (federation SDK verbs, a hostile network, more than two domains — the first time several of its claims could be *stated*); the contracts axis' **two open design decisions decided and built** (commitment offers/awards carry provenance, because a pure award rule over forgeable inputs checks that the rule was applied and not that the inputs were real; and the federation edge meters calls per partner, the mirror of `GatewayPool` on the other side of the same edge); and a **security fix** — a deployment whose only credential model was `gateway_named_tokens`, the configuration the config docs tell operators to *prefer*, had been running an **open gateway** since 2.10.0.
