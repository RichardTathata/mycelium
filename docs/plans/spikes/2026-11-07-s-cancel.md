## The question

From the plan, verbatim: *a `call:` mandate minted at admission reaches the provider before its checkpoint gossips.
Carry the first checkpoint **inside the envelope** beside the mandate, through `assess` and `admit_after` to `begin`;
measure the added bytes and the admission latency against today's grant path; show a revoked term read `Refused`; and
two bounds the row must state.* **Done when:** *a call registered with `begin` without a KV round-trip, or the bounded
wait's cost measured; the memory-reclamation hook shown on 10⁵ calls.*

**Answer: carry it.**
- A provider that has never seen the checkpoint establishes the `call:` mandate from the envelope and registers the work
  with `begin`. There is no KV read and no wait.
- The cost is 360 B on the presented mandate. **At the provider**, it adds nothing over today's grant path. At the
  gateway it costs three signatures per call, about 38 µs. The durable write of each call's first checkpoint was **not
  measured**.
- The rejected alternative is waiting for the checkpoint to gossip. One hop is fast on loopback, 0.42 ms at p50, but
  **under a partition the wait has no bound**, which is why it is rejected.
- Without either, what happens depends on the rule:
  - where a rule admits the call without a mandate, the call is not registered, and a cancel cannot stop it;
  - where a rule requires one, the `Unknown` mandate is refused (`src/agent/action_evaluator.rs:2106–2116`).

## What was built on the spike branch

- **A `call:` scope** (`CALL_SCOPE_PREFIX`, `Mandate::is_call`) in `src/mandate/grant.rs`.
  - It is entitled as `grant:` is: by the prefix, or for **any** `node:` issuer under `entitle_grants_from_fleet`. That
    is too broad for I4; see the row.
  - It is exempt from the verifier's per-scope epoch bookkeeping.
- **`PresentedMandate.checkpoint: Option<SignedRevocationCheckpoint>`** (serde default; omitted when `None`).
- **`ExecutionAuthority::assess_with_local`.** `assess` delegates to it.
  - For a `call:` mandate it offers the carried checkpoint, and this node's own KV copy of the call's checkpoint, **only
    once the mandate has verified**: issued, entitled, current, possessed.
  - It offers them only for the mandate's own authority and scope.
  - It then judges the mandate as a grant is judged. `Revoked` gives **`Refused(MandateRefusal::Revoked { term })`**, a
    new variant.
- **The callers.** `provider_enforcement::admit_after` and the gateway's preflight (`authz.rs`) read the call's KV copy
  (`local_call_checkpoint`) and pass it in.
- **The feeder.** `feed_grant_checkpoints` now **skips a `call:` checkpoint for a scope this node has not admitted**
  (`admits_call_scope`). See H2 below.
- **Reclamation.**
  - Each admitted `call:` scope's window is kept in a map, plus an expiry queue ordered by the window's end. Both live
    inside the authority's existing state (lock-order row 43).
  - Every sweep reclaims at most **`RECLAIM_PER_SWEEP` = 1 024** expired scopes, only once their window has passed.
  - `RevocationView::forget` drops a scope.

## What ran

Everything ran on an Apple M2 Max, macOS, Rust 1.96.0, at the tagged commit.

- **In process, release build:** `cargo test --release --lib --features tls,compliance,a2a spike_s_cancel::s -- --nocapture --test-threads=1`
  (`src/agent/gateway_authority.rs`, module `spike_s_cancel`, tests `s1`–`s6`).
- **Two TLS nodes, debug build, in process, on loopback:** `cargo test --lib --features tls,compliance,a2a grant_tests::spike_s_cancel -- --nocapture --test-threads=1`.
  This runs two tests, `spike_s_cancel_end_to_end_over_two_nodes` and `spike_s_cancel_reclamation_with_the_feeder_running`.
  - Node A stands in for the admitting gateway. It mints the `call:` mandate, holding and issuing it itself, signs the
    possession proof and the first checkpoint, and calls B's slow tool (3 s) directly.
  - B is the provider: provider enforcement on, freshness window *F* = 2 s, so it sweeps every 100 ms. The call is
    admitted by a rule that does not require a mandate.
  - The first checkpoint is never written to any KV. A revokes by writing the revoking checkpoint under the grant key
    family, a plain write, which B's feeder offers.

## The two bounds the row must state

1. **A term revoked between the gateway's framing and the provider's `admit_after`.** The call carries a checkpoint
   that predates the revocation, so the provider admits and registers the work, and stops it only when the revoking
   checkpoint arrives.
   - **The cancel's effect is the gossip latency, plus the sweep interval, plus the class's `drain_bound`** (for a
     `ReauthorizeAt` class, skew + interval + cancellation latency + confirmation latency).
   - The sweep interval is the gate's freshness window *F* / 20, clamped to 100 ms–5 s.
   - Measured on loopback, n = 20: 42.1 ms at p50 and 45.2 ms at p95 from the revoking write to the call ending, with a
     100 ms sweep and a handler that stops at once.
   - **This bound needs the revoking checkpoint to arrive.** Under a partition, or for a class whose `drain_bound` is
     `Unbounded`, it has no bound. Then only the mandate's own window caps the work: the sweep ends work past its
     `not_after_ms`.
2. **`drain_bound` is `Unbounded`** for the unenforced and unconfirmable classes (`src/mandate/authority.rs`; S4).
   There a cancel writes `Refused` and stops nothing the resource can confirm. The cancel's receipt has to name the
   drain class it hit, or answer `DeliveryUnknown`. **The spike did not build that receipt.**

## What it could not do, or did not do

- **No gateway door mints a `call:` mandate.** A node minted it by hand, as the holder of a member's direct call. The
  holder as the gateway behind a client's call, the second mandate slot and the gateway's entitlement are all I4's.
- **The revoking checkpoint was written with a plain KV `set`** under the grant key family. I4 needs its own `call:`
  key family and feeder, written durably.
- **Not built:**
  - the cancel receipt;
  - the cancel-forward RPC kind;
  - A2A `tasks/cancel`;
  - MCP `notifications/cancelled` and its id → term table;
  - `max_drain_secs`, `grant_retention_secs` and the `cancellable` key;
  - the window table across a restart.
- **`PresentedMandate` is public.** The new field broke six literals outside the library at `e8e58b2e`:
  `tests/gateway_mandate_external.rs`, the examples `authority_drain`, `confined_fleet_node` and `composed_commit`, and
  two in `mycelium-effects/tests/composed.rs`. The SDKs carry the same shape as JSON: `PresentedMandate` in
  `mycelium-ts/src/a2a.ts:10`, and the `{"grant", "possession"}` dict in `mycelium-py/src/mycelium/a2a.py`. An optional
  field is additive there, but each type has to learn it.
- **Memory:** every offered checkpoint opens a revoked-set entry for its scope even when it revokes nothing.
- **Not measured:**
  - the full envelope's bytes;
  - the gateway's durable write;
  - a real network or load;
  - a restart in the middle;
  - the two-node figures in a release build.
